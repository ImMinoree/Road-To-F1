# Countdown and controllable handling

The HUD reads the existing GameMode light events: red lights 1–5 show
5–1, and the existing lights-out release shows START. Each label fades
in and out and has a small settling scale animation. There is no additional
countdown timer or movement gate. Restart clears the presentation timestamp.

Handling keeps the fixed 240 Hz tire-force solver, collision sweeps and shared
player/AI dynamics. The tune adds gradual steering response and a speed-based
curvature request envelope, with grip-aware rear drive/brake torque moderation.
It does not clamp lateral velocity or directly impose yaw. These are configurable
game-control aids and plausible starting values, not measured kart calibration.

Defaults on `KartTireDynamics`:

- SteeringResponseSeconds: 0.16
- SteeringLateralAccelerationG: 0.85 (requested curvature envelope)
- FrontCorneringStiffness: 12000 N/rad
- RearGripScale: 1.20
- SlidingGripDrop: 0.06
- RearLateralGripReserve: 0.95 (maximum reserve, used only when cornering demands it)

The underlying 24-degree low-speed lock and existing speed/power settings remain.
Set the steering envelope and rear grip reserve to zero to disable those two
assists, or the response time to zero for the former rate-only steering response.

`native_results.txt` compares identical corner, brake, surface and recovery inputs
with the prior tune. `pie_result.json` and `pie_trace.csv`, when generated by
`Tools/validate_countdown_handling_pie.py`, record actual PIE checks and map hashes.
The handling portion uses a transient off-circuit pad; the countdown captures use
the actual starting grid. The script never saves the map.
