# Editable tire barriers

`TireBarriers.blend` contains separate, named individual tires under each module pivot. The supplied `SM_Tire_Black.blend` is unchanged; its byte-for-byte backup is `Backup/SM_Tire_Black.original.blend`. The source was a 0.62 m torus; the new closed-section lathe is approximately 0.55 m diameter, 0.184 m wide, with a 0.326 m bead opening. These are plausible reused passenger-car tire dimensions for barriers, not kart road-wheel dimensions.

Three modules (Black, Alternating, Mixed) each contain 4 adjacent columns of 3 tires, approximately 2.19 m long and 0.552 m high. Pivots are at bottom centre. Export axes are -Y forward, Z up; Blender metres import as Unreal centimetres. Five FBXs in `Exports` include both single-tire colours. `Textures` contains generated 1024 px seamless base-colour, roughness and tangent-normal maps. Use NormalDX in Unreal and NormalGL in Blender. Blender's connected Noise -> Bump -> Principled normal chain adds microscopic detail; portable textures approximate that grain in Unreal. The UE master also adds restrained instance colour variation.

Build with `D:/Boring/blender.exe -b --python Art/Trackside/TireBarriers/generate.py`; verify the saved source, FBX round trip and safe offset paths with `plan_and_verify.py`. Run `Tools/tire_barriers_run.py` with the Unreal Editor's Execute Python Script and `-KartDynamicsTest` launch flag to import, ground-fit, check collision and capture the stopped kart's driver-eye view. Mesh LOD/collision tools require the live editor, not the Python commandlet. No C++ build is needed.

Unreal assets live in `/Game/RoadToF1/Trackside/TireBarriers`. Both single tires and module meshes have simple convex collision and four LODs. The base meshes have 13,120 triangles per tire; automatic LOD reductions retain 35%, 12% and 4%. Runtime placement uses shared single-tire HISM foliage types, not duplicated full module geometry. Two 24-column outside-corner walls follow sampled offset curves from the existing route. Source asphalt/curb/runoff clearance is measured before live ground fitting. Existing race geometry, staging, lighting and actors are preserved.

Validation evidence is in `Evidence/TireBarriers`: actual close-up and module Blender renders, FBX round-trip results, Unreal import and live collision reports, and the PIE driver-eye capture when successful. Inspect `validation.json` and any error files; script completion alone is not acceptance. Tires are static rigid geometry with simplified collision (including filled centre holes for vehicle collision), no straps, deformable sidewalls or impact simulation. No full-race performance benchmark or complete driven lap is claimed.

Rollback: run `Tools/tire_barriers_remove.py` in the live editor to remove only this task's two foliage types from DesertKarting_Visual. Generated assets remain available for reuse. A pre-task map copy is also preserved in `Backup/DesertKarting_Visual.before_tire_barriers.umap`; restore it only if no later map edits need preservation. No commit or push is performed.
