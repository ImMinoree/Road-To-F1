# DesertKarting visual variant

Open `/Game/RoadToF1/Maps/DesertKarting_Visual`. The default game mode is `BP_DV_EnvironmentPreview`, with the invisible engine SpectatorPawn for free-fly environment inspection. It does not spawn a kart or driver. Run `Tools/OpenDesertVisual.ps1 -Editor` to edit, or run without `-Editor` for the environment preview. Add `-Drive` to use the original ProofPawn first-person driving, W/S throttle/brake, A/D steering and R reset. This is the unchanged temporary physics, with no visible cockpit or driver. `-Profile Validation` uses Epic/100% rendering; Balanced uses High/75% at 1920×1080.

## Reversibility

`/Game/RoadToF1/Checkpoints/DesertKarting_BeforeVisual` is the original level before any kart hiding. The original `/Game/RoadToF1/Maps/DesertKarting` receives **only** reversible kart visibility/folder/tag changes. Its layout, materials, collision and driving mode remain unchanged. All art improvements live in the new variant and `/Game/RoadToF1/DesertVisual` assets. Existing meshes, textures, materials, Blueprints, C++ and project settings are protected by SHA-256 checks.

Eight source actors contain all 48 race karts and their seated drivers, separate from the environment and grandstand spectators. In both maps these actors are retained in `_Hidden_Restore_Karts`, tagged `DV_RestoreKart`, with Hidden In Game enabled and mesh-component Visible disabled. Their mesh assets and collision settings are untouched. To restore them, run `Tools/desert_restore_karts.py` through Unreal's Execute Python Script command. It restores visibility in these two maps only. Alternatively toggle component Visible and actor Hidden In Game for the tagged actors manually. The checkpoint retains the original unhidden state.

## Four completed implementation passes

1. **Track:** new original 2 m asphalt aggregate PBR set with DirectX normals and roughness, plus a world-space racing-rubber atlas generated from the source centreline. Painted kerbs/runoff use chipped coating and concrete variation. No road vertices, transforms, collision meshes or body setups change. World coordinates compensate for missing GLB UVs.
2. **Pits:** separate bevelled visual copies of stone/plaster structure and transporters; 21 reusable shutter/frame/cap/handle modules and five racing banners. Masonry, corrugated metal and woven fabric use dedicated texture sets. Shutters are relief geometry over the original flat openings; there are no new interiors. No lights, emissive fixtures, exposure, sky or fog settings are adjusted.
3. **Trackside:** 82 flat block barriers receive rounded molded covers, handles, reflector panels and feet. Original blocks remain invisibly in place for unchanged collision. Four tire stacks, 14 detailed tool chests, 20 drain grates, five extinguishers and 13 rounded pit-sign pods use shared instanced geometry. Original perimeter tires/fencing remain, with material detail.
4. **Stands:** filter only the identifiable seat cubes from visual copies of the red/blue source mesh groups, preserving spectator bodies. Add 1,008 reusable 488-triangle bucket seats in three colours, and 245 caps in three colours on existing spectator heads. Original crowd geometry remains efficient shared material batches. It is still visibly simple at close range.

Six original 1024-pixel PBR sets, a wear mask and a 2048-pixel rubber atlas are generated by `Tools/desert_visual_author.py`, using installed Blender/Numpy only. No marketplace assets, downloaded packs, AI textures or dependencies are introduced. Materials are shared masters/instances; 15 foliage/HISM types serialize the 1,417 detail instances with nonblocking collision and 180–350 m culling. Source geometry copies retain separate feature/material buckets. `DesertVisual_Details.blend`, exported FBXs and the manifest preserve the modeling pipeline without touching the original Blender scene. Modular prototypes are retained hidden at their export origins in the details blend; Alt-H reveals them. Derived building/crowd copies are reproduced from the source GLB by the author script and retained as separate FBXs.

## Validation

`Evidence/DesertVisual/01_Track.json` through `04_Stands.json` record ordered implementation. `implementation.json` records protected-file hashes, unchanged collision/light signatures, sources, instance counts and remaining placeholders. Real rendered comparisons and live-editor road probes are generated by `Tools/desert_visual_capture.py`; it retains each Unreal screenshot task until completion and uses explicit cameras. Baseline and Visual use identical cameras, scene lighting and graphics settings.

Remaining limitations: original low-detail spectator anatomy, parked road-car and palm/shrub silhouettes; basic perimeter fence spacing; closed garages without interiors. This is an authored stylized pass on the supplied model, not a claim of shipped Fortnite asset quality. More convincing near-camera spectators and vegetation require suitable authored/rigged art assets.

The initial real renders identified mirrored pit text, incorrect world-space backface normals on some ground cover, stretched vertical texture projections, and disconnected dots in the rubber atlas. `Tools/desert_visual_refine.py` applies the observed corrections without touching lights or collision. Grass uses the native two-sided geometry normal; the other shared masters include two-sided sign and surface-oriented projection. The final rubber atlas uses continuous sampled tyre lines. These corrections are included in the author/import scripts for reproduction, and recorded in `Evidence/DesertVisual/refinement.json`.

## Final measured result

Final screenshots were inspected for all five views. The backface ground artifact is corrected in the final barrier and aerial renders; pit text reads correctly. Live editor checks pass all 15 road probes on both maps, with zero visible kart actors. The standalone environment preview log identifies `BP_DV_EnvironmentPreview_C` and only `SpectatorPawn_1`. Read-only verification confirms 126 protected original asset/source/config/map files plus the original GLB are unchanged. The restore checkpoint is serialized as a real `.umap` with all eight original kart groups visible.

On RTX 3080 / i7-10700KF, 1920×1080, 75% rendering, identical High scalability settings and no concurrent editor: baseline 180.12 FPS / 5.552 ms; final variant 177.39 FPS / 5.637 ms, a 1.53% frame-time increase. Each standalone run lasts 20 seconds and samples the final 10 seconds. This is a short temporary-pawn test, not a full lap or a 20-kart race. CSV boot profiling can change initial movement after loading stalls; final test positions are recorded rather than assumed identical.

Separate CSV warm-tail samples (200 frames, earlier than the FPS measurement window) show approximately 545 → 671 total RHI draws and 47 → 66 base-pass draws. GPU time is approximately 4.99 → 5.27 ms. Existing shadow-depth rendering is the largest GPU scope, approximately 1.98 → 2.08 ms; its light settings were deliberately preserved. These nested GPU scopes must not be summed. `Evidence/DesertVisual/final_validation.json` contains exact samples, settings, source checks and honest remaining limitations. The previous project-wide `Evidence/Runtime.json` is restored after benchmarking.
