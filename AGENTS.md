# Development reporting

The project owner wants human-readable reports included with feature commits and GitHub pushes.

- Add or update a Markdown report in `Docs/Game development process/` for each meaningful feature or improvement completed for the owner.
- Use a descriptive heading: `Game development process - <what changed>` and a dated filename. Update the report index.
- Write from the human project owner's perspective ("I added...", "I improved..."). Credit the owner as the developer and state Codex's implementation, testing, and documentation assistance accurately; do not imply unaided manual work.
- Describe the change, its purpose, files/assets, actual validation, and remaining limitations. Link supporting evidence using repository-relative paths so GitHub links work.
- Record only work and checks actually performed. Distinguish historical validation from the current evolving project state.
- Stage the relevant report alongside its feature when preparing an authorized commit. A chat reply alone is not the permanent report.
- Do not interpret this reporting preference as standing permission to commit or push. Follow the owner's current authorization and any pending approval requirements.
